# FR-15 首版实现与证据

当前交付为意图理解模块、状态更新器和 Agent 首版接入；FR-15 整体仍未验收。未实现的目录运营、完整多轮效果评测与交互细节不以本轮测试替代。

## 已实现

- `intent/taxonomy.json`：版本化六类商品客服目录，含定义、正例和边界。可通过 AgentRunner 的 intent_taxonomy_path 替换；目录 hash 写入运行配置。进度查询等标签只表示理解，不声称已有下游工具。
- `intent/service.py`：模型一次返回 delta；校验目录、唯一目标、原文引文、合法迁移、对象属性来源、版本、幂等及作用域。新增、多诉求、纠正、暂停、恢复、撤回、条件/历史待定和歧义分开处理。不接业务工具。
- 原文位置由严格跨度验证；当位置不准确但引文在当前原文唯一出现时，后端确定性定位并记录 reported/resolved 差异。不存在或有多个匹配时拒绝。原始 delta 保留，应用历史保存解析后的证据位置。
- AgentRunner 的真实 Agent 默认先执行 intent；固定流程对照不默认加入，旧 fixture 默认关闭，可显式启用测试。调用通过 MeteredGateway 计入原有预算，仍预留两次回答核验。新旧提示/配置变化导致旧未完成 run 的配置检查拒绝，不能悄悄用新配置继续旧实验。
- 状态随既有会话 task/run JSON 原子保存，无新增表迁移。Sessions 的 revision、消息幂等与单活跃 run 机制提供并发保护；AgentState 纳入字段，避免图执行丢失。商品切换任务隔离。
- 理解状态进入规划上下文；语义歧义进入现有 clarify 等待流程。理解失败停止本轮，并保留不确定标记到后续轮次；新增明确办理诉求前不沿用旧 active 请求提交。
- prepare/commit 工单增加理解状态门禁：暂停、撤回、条件、未理解或未消除的不确定状态不准办理；通过理解门禁仍须现有参数绑定确认、授权及执行账本检查。

## 验证

开发过程中曾发现严格 Python tuple 与 JSON array 的解析差异、持久化格式一致性、冻结模型对象的修改限制及否定暂停语义边界，均保留失败记录并修正。测试只使用明确标注的 fixture，不冒充模型识别效果。

接入阶段后端全集 232 项通过（1 条依赖弃用警告）；后续状态保护改动另跑 Agent/API 回归。最新意图专项 11 项通过，覆盖迁移、原文依据、幂等、作用域、歧义、失败停止、状态继承/记账及办理门禁。Ruff/Mypy 通过。

真实三轮最终复验：

1. “帮我申请维修。” → active service.apply。
2. “先别申请，维修收费怎么算？另外，怎么安装这个商品？” → 原申请 suspended，同时新增 service.rules 与 product.howto。
3. “继续刚才的维修申请。” → 同一申请恢复 active，两个咨询目标仍保留。

以上结果经程序逐条断言，并核对冻结模块 hash。最终批次 3 请求，开发定位与复验累计新增 11 请求，总账 **854/870**，剩余 16。所有失败请求计数，无自动重试、无业务执行。证据目录 `artifacts/shopguide/intent-v1-reviewed/`，此前各阶段目录保留。真实验证是三轮开发 smoke，不是独立测试集准确率，也不是完整客服端到端验收。

## 未关闭

首版尚无：完整目录审批/迁移运营、独立的全局约束与诉求先后关系协议、显式对话行为字段、长期原文压缩与来源轮次索引、全部 INT-01–12 场景及真实中文分组数据集/三组消融。模型得到的历史仍为现有窗口，长期原文引用并未由状态摘要完全解决。多条澄清暂显示第一条，由后续轮次继续解析；缺业务字段的追问策略仍需真实产品验收。

条件诉求不会自动转成可执行请求；被撤回目标不能通过 resume 复活。理解模型仍可能误判，目录和提示不能代替真实效果验证。未建设真实会员退款/续费工具，暂停或撤回也不声称撤销已发生的业务副作用。

Agent/API 联合回归记录为 40 通过、4 个新增门禁 fixture 缺必填 reason 的失败；补齐 fixture 后，包含这 4 项的最新意图专项 11 项全部通过。未改写首次失败日志。证据保存在最终目录的 intent-tests.txt 与 agent-api-regression-before-fixture-fix.txt。
