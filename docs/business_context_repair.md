# 工单结果与最终回答的信息传递修复

## 修复

此前主控已查询到工单结果，但 FixedRAG 的 Writer/Verifier 只接收原始混合问题和说明书，导致将工单部分误判为资料缺失。本轮新增 DeliveredServiceQuery 严格契约：固定查询工具来源、模拟标记、ok/empty、编号集合和是否还有记录，校验状态与记录一致性。不传入任意工单摘要或模型生成的业务解释。

Agent 保存原查询参数；最终生成前通过 SimulatedService.query 再核对当前用户、商品和型号的查询范围，刷新独立展示的查询结果，并将同一份规范化上下文传给 Writer 和 Verifier。缺少查询参数来源时拒绝最终化。当前为只读查询，不增加模型调用，也不触发工单创建。

新增 separately_delivered_service_query 告知模型：业务查询已执行，并由界面独立展示。empty 是已完成且无匹配记录的查询，不是工具不可用。Writer 只写说明书支持的指南；Verifier 综合独立查询卡片判断响应范围，同时继续逐条核验手册 claim。工单编号不成为 evidence_id，工单状态不使用手册引用。complete=false、未知来源或无依据步骤仍拒绝。

提示版本 fixed-rag-v8。固定问答未提供查询上下文时不注入此字段；保留原声明与核验流程。本轮没有修复或掩盖此前子 Agent 的所有工具参数错误。
