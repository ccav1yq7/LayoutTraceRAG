## 暴露的主要缺口

1. 意图层：恢复路由后的场景仍有两次 INTENT_UNDERSTANDING_FAILED，且记录没有保留更细的失败原因；不能断言都是服务故障。明显咨询/原图请求出现多余澄清，专家角色与人工诉求也有混淆。
2. 待确认状态继承：当前历史查询不包含 WAITING_CONFIRMATION，导致后续消息不能完整继承待办理 goal。确认版本门禁阻止了误操作，但不能代替正确意图状态管理。
3. 混合核验稳定性：上轮业务上下文传递修复在定向样例通过，但本轮仍有 answer_incomplete。真实 draft 只包含手册支持的启动方式，查询结果也保留；不能重新将这次失败都归因为旧的上下文漏传，需单独诊断 Verifier 完整性判断。
4. 图像链路：本轮所有计划消息的模型 image_inputs 合计为 **0**，policy 子 Agent 也未触发。因此浏览器能打开来源图片，不代表模型实际观察图像或政策子 Agent 已验收。
5. 工单查询的模型输出可靠性和缺图提示仍需完善。多项安全检查虽通过，不能补偿功能任务未完成。
