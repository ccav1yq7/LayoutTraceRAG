# ADR 0009：回答覆盖率排查、图片来源绑定与拒答分类

日期：2026-09-10。范围仅为固定图文 RAG 的回答覆盖率，不修改多页检索或 32 条证据预算。

## 验收条件

1. 先复现失败阶段和具体条件；旧 50 题实验、第一次失败及仅改提示的负结果保留。
2. 模型明确选择的图片必须来自当前允许集合，其图片来源引用可由可信登记解析。
3. 不补写操作文本、不选择替代图、不引用 gold、不删除图片/授权/语义校验。
4. 正常拒答不计入回答覆盖率；结构错误与拒答可以区分，生产日志不保存模型原值。
5. 独立核验仍检查全部 claims 与 step/image 对；不支持、不完整或重复/漏项继续拒绝。

## 已复现问题

四本不同手册的四个 B2 样例均复现：Writer 选择了允许图片，却只引用文字证据，
没有引用该图片所属的证据。`render_answer` 正确拒绝这些不一致的组合。
两个 B1 样例实际想拒答，却遵循“摘要必须引用”而附上 summary_evidence_ids，
违反现有拒答契约。它们不能被统计为“本来应该回答却因检索失败”。

仅增加映射和提示后，B2 四例仍有三例失败，说明依赖模型重复抄写图片所有者关系不稳定。
该负结果保存在 coverage-investigation/after，不覆盖。

## 决策

- Writer 输入增加 `display_asset_evidence`（选中图片→当前证据的所有者 ID）。选图输入增加
  `allowed_asset_ids`，其余 evidence 中的图片 ID 按实际可选集合过滤。
- 对 Writer 在某一步**明确选中的合法图片**，后端查找当前 lookup 内唯一的登记所有者，
  将该图片来源绑定到该步骤及对应 claim/citation，再进入原渲染和独立语义核验。
  这是对已选图片的来源解析，不是替模型新增图片、补写业务操作或用 gold 修正答案。
- 未选择的图片不添加；未授权/未检查的图片继续拒绝；所有者缺失或歧义拒绝；原有
  文本引用仍必须合法，不能用图片来源替换或删除非法文本引用。
- 新增 `image_reference_bindings` 记录每个步骤新增的来源 ID 与依据。调用者能区分
  Writer 原始引用和后端派生的图片来源，不能把派生部分描述为模型原始输出。
- 原 `render_answer` 不改，仍验证步骤与图片来源一致、来源字节、型号/权限与文本边界。
  绑定后的完整答案仍送入独立核验；不支持、complete=false、重复或漏项仍失败。
- 提示版本 `fixed-rag-v4`：明确 answered/partial 的引用规则，以及 abstained 时引用/
  步骤/前提均为空的例外；Verifier 收到明确 `required_claim_ids`，不通过删掉不支持项来满足结构。
- 配置登记 `image_reference_policy=explicit-image-registered-owner-v1`。旧冻结运行源码指纹
  自然失效，不能用旧 campaign 继续跑新逻辑或混合新旧分数。
- `failure_detail` 记录阶段、类别、受控原因以及 Pydantic 错误路径/类型，不记录模型原值、
  原始异常消息或上下文。核验完整性另记计数、ID 集合是否匹配和 model_complete，
  区分“未覆盖全部要求”和“已覆盖但声明不完整”。
- 正常 WRITER_ABSTAINED 在 PM209 预测中记为 abstained；公共答案仍无步骤/引用，
  覆盖率和评分分母不变，不将拒答改成 partial 来提高分数。

## 验证和限制

小规模调用遵循用户“50 次以下不用问”的授权；本轮预设总上限 48，实际 47。
四个定向 B2 案例从 0/4 可交付变为 3/4 带图交付；剩余一例 complete=false，保留失败。
两个 B1 例变为正确分类的拒答，覆盖率仍为 0/2。额外四个开发例 3/4 带图交付，
一例重复 claim 核验记录，继续拒绝。均非随机代表性样本，不能外推完整 50 题覆盖率。

修改后的更详细核验计数日志由离线测试验证；真实探测保留当时原始 run 与独立观察记录，
不倒填新诊断字段。多页 `_retrieve` 方法 AST 与原冻结版本一致，未处理证据分配问题。
