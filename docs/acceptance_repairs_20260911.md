# 2026-09-11 验收失败项修复

针对第二版完整验收暴露的问题，分三次冻结代码和定向复验。没有覆盖此前失败或将不同版本合并成一次全量通过。

## 工程修复

- 未确认商品时，真实 Agent 直接进入商品选择澄清，不先让意图模型猜测商品类别；该路径不调用远端模型。
- 意图输入增加已有目标的合法操作清单及不冲突的新 ID 示例。新增 continue 表示继续 active/current 目标，update 表示属性更新；两者不能恢复 withdrawn。未知标签、冲突属性、非法迁移仍拒绝。
- 完全相同的重复属性可去重并记录 normalizations；不同值或依据的冲突不被覆盖，原始 delta 和来源审计保留。
- Planner 的非业务说明 reason 可使用后台默认值。进一步离线复现确认：旧上传失败的 too_short 对应空 missing_fields 列表；合法的非空澄清问题现在可使用通用 clarification 类别。空问题仍拒绝。诊断白名单加入 reason/missing_fields，避免隐藏合法字段名。
- Writer 主动拒答现在作为 completed/abstained 客服结果返回，不再冒充 VERIFICATION_FAILED；没有生成被拒绝的操作步骤，也不计为 answered。
- unresolved_items 的限制说明转为 inference claims，引用本次检索上下文并参与全部必需核验；仅在支持性和完整性核验通过后展示为 partial。不会直接丢掉不支持内容以获取通过；夹带操作或不实结论仍被拦截。
- 本轮明确只有工单查询（以及暂停/撤回控制）时，查询后可以直接返回，历史指南目标仍保留但不强制重答；当前确实包含指南的混合请求继续完整处理。
- 检索返回证据时检查登记配图的本地可用性。文件缺失传递 IMAGE_UNAVAILABLE 给答复和界面，而不是只有调用图片观察工具时才发现。权限或内容完整性错误不会伪装成普通缺图。
- Writer 明确使用用户语言直接答复，减少第三人称描述用户请求或内部工具流程。

业务确认、主体/型号隔离、图片真实来源、独立核验和共享调用预算继续保留；未新增人工交接或业务自动授权。
