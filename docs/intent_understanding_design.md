# 客服意图理解首版设计（待实现）

本记录根据用户提供的意图感知方案及当前代码审阅整理。这里的能力均为拟议设计，不表示已经实现或验收；未验证附件中的厂商资料，不引用其为项目效果依据。

## 当前缺口

Sessions.submit 保存最近三轮问答；AgentRunner._view 向规划器传递最近两轮历史。当前每次 PlanDecision 选择一个后续动作，没有独立的多诉求状态集合、意图变化协议、来源轮次或意图目录版本。任务切换会清理原任务上下文，不能直接作为暂停、恢复诉求的实现。

## 首版范围

按现有商品客服范围组织目录：使用方法咨询、故障排查、售后规则咨询、提出售后办理请求、进度查询、转人工。目录描述区分“咨询怎么办”和“要求立即办理”，并注明哪些下游能力已支持；识别到诉求不代表已有对应工具。会员业务示例仅用于状态协议测试，不新增会员办理接口。

先以进程内模块实现，不拆微服务。模块输入为当前原文、带角色和稳定轮次标识的历史、最近客服提问、当前意图状态、目录版本和预期状态版本。输出为结构化变化与歧义，不返回业务执行结果，不调用业务工具。

## 协议与状态

每个诉求独立 goal_id。模型提出 add/correct/suspend/resume/withdraw；程序校验合法迁移、原文证据跨度及来源轮次，再原子更新状态。active/suspended/withdrawn 与 current/conditional/hypothetical/historical/negated 分开表达；条件诉求不得直接激活执行。resume 只能恢复暂停项，撤回项不能被无依据复活。

真实多诉求与一个诉求的多个候选解释必须使用不同字段。对象属性保留明确陈述或推测的来源；显式纠正优先，未提及的已有字段保留。缺办理字段不等于意图未知；语义歧义、对象歧义、超出范围和目录未覆盖分别返回。

轮次幂等键和预期状态版本拒绝并发覆盖；相同轮次不同内容拒绝重放。目录只能来自发布版本，模型不得自创标签。暂停/撤回约束传递给规划层，但意图状态绝不是业务授权；现有 prepare/confirm/commit 及幂等审计继续负责执行。

## 接入方式

先在独立契约与 reducer 测试中验证状态，再接入一次每轮理解调用，通过现有 MeteredGateway 记账，预留 Writer/Verifier 预算。持久状态按会话/商品任务隔离。失败时保持原状态并明确标记本轮理解未完成，不凭空更新；新消息可能撤回旧请求，因此理解失败时不能依据旧 active 状态继续提交业务。

理解结果供 AgentRunner._view 使用；前端展示必要的澄清，不展示完整技术状态。固定 B1/B2 评测不默认增加意图调用，避免改变其对照协议。

## 验收

固定同末句不同上下文、否定纠正、多诉求、暂停恢复、条件退款、对象纠正、未知诉求及并发重放样例。程序测试只证明状态约束；真实模型识别需独立评测，按会话划分并报告多诉求精确匹配、状态变化准确性、误执行风险、澄清负担及用量。不得把合成 fixture 通过当作真实中文理解通过，也不把模型自报 confidence 当作校准概率。

建议实施顺序：发布目录与协议 → 原子状态管理和离线测试 → 受预算约束的模型适配 → 会话/规划接入 → 固定小样例真实验证。上线或全量验收仍须单独完成。
